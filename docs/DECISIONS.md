# Decisions

One dated line per decision taken while implementing [PLAN.md](PLAN.md), so
the next session does not decide it again. Newest last.

- 2026-10-20 — Secrets for the core live in the host's macOS Keychain, account `fridolin`: `fridolin.tailscale.authkey`, `fridolin.b2.vault.key`/`.keyid`, `fridolin.b2.snapshots.key`/`.keyid`. `fridolin core start` (M1) reads them from there.
- 2026-10-20 — Tailscale: the policy file owns `tag:fridolin-core` and `tag:fridolin-node` (`autogroup:admin`). The core's auth key is reusable, not ephemeral, tagged `tag:fridolin-core`, 90 days; the node key waits for M2.
- 2026-10-20 — B2: buckets `fridolin-vault` and `fridolin-snapshots` in eu-central-003 (endpoint `s3.eu-central-003.backblazeb2.com`), private, SSE-B2, no object lock; both keep prior versions 30 days. One application key per bucket, restricted to it.
- 2026-10-20 — SQLite driver is `modernc.org/sqlite`. The DSN keeps the cgo driver's behaviour: `foreign_keys(1)`, `busy_timeout(5000)` (mattn's default; modernc has none) and `_time_format=sqlite` (mattn's text format, so old and new rows compare). whatsmeow's dialect name stays `"sqlite3"`.
- 2026-10-20 — The config version is `config.Version` in `internal/config/config.go` (PLAN.md calls it `currentConfigVersion`).
- 2026-10-20 — Windows process groups are `CREATE_NEW_PROCESS_GROUP | CREATE_NO_WINDOW` at start and `taskkill /T /F /PID` to stop, not the Job Object PLAN.md names: `exec.Cmd` has no hook between creating and resuming the child, so a job assigned after `Start` misses what the child starts first; and `KillProcessGroup(pid)` is called with nothing but a PID (after a crash too), so a job handle would have to live in package state, which `internal/platform` must not hold. Cost: taskkill walks parent PIDs, so it misses the children of a process that has already ended. Revisit when M2's node agent runs executors on Windows.
- 2026-10-20 — The Windows bridge lock is `LockFileEx` on one byte at offset 2^62 of `bridge.lock`, not on the PID: Windows locks are mandatory, and a second bridge must still read who holds it.
- 2026-10-20 — `platform.Exec` on Windows (no exec(2)) starts the same program as a child with the console and standard files, waits and exits with its status; each dashboard restart leaves one waiting parent.
- 2026-10-20 — On Windows the bridge reads no ACLs: the data dir's owner and mode checks say nothing, `O_NOFOLLOW` is `FILE_FLAG_OPEN_REPARSE_POINT` plus refusing a reparse point, and the hard-link count comes from `GetFileInformationByHandle` (`fsx.LinkCount`). Process start times are not read either, so no run is recorded and none is stopped after a crash; `--log-file` does not rotate (Go opens files without `FILE_SHARE_DELETE`); the tmux viewer and the folder dialog are unavailable.
- 2026-10-20 — M0 step 2 stops at a Windows build and `go vet`; running `claude` there (its `claude.cmd` shim through `cmd /C`) waits until Windows runs brains. `TestImportRules` now also checks the windows file set.
- 2026-10-20 — Windows in CI: a `go-windows` job (windows-latest, cgo off, no race detector, `go test -short`) beside the macOS/Linux matrix; `make vet` vets GOOS=windows too. Release archives for windows/amd64 and arm64 are `.zip` with `fridolin.exe`, cross-built on Linux.
- 2026-10-20 — The M0 data-layout step leaves `config.Version` at 2: it only adds the sections `core`, `vault`, `nodes` and `policy`, all off by default, and renames, removes or re-means no key, so a version 2 file keeps its meaning and needs no `configMigrations` step (PLAN.md assumed one; a bump would only make every older build refuse the file). A step comes with the first setting these sections supersede.
- 2026-10-20 — The new sections are live settings (`config.Live`), not restart (`Boot`) fields, while nothing runs on them; the code that starts the tailnet, the lease or the node port marks its fields `Boot` in `internal/config/fields.go`.
- 2026-10-20 — Data-dir paths come from `config.Layout` (`Boot.Layout()`); its folders are made lazily with 0700 by their feature (`config.EnsureDir`), never at startup. Packages that may not import config (platform, plaud) are handed the path: `platform.AcquireLock` takes the lock file's path, `plaud.Options.SiteDevices` the site's devices.json.
- 2026-10-20 — On Windows the bridge (the core) runs in the Linux container, as PLAN.md's platform matrix says; natively Windows runs only the node agent (M2). CI's go-windows job builds and vets everything but runs only the tests of packages that run natively (`WINDOWS_PACKAGES` in ci.yml); the bridge's own packages (app, backup, brain, claudecli, cli, config, fsx, httpapi, …) fail there on fixtures that write Windows paths into JSON unescaped and on HOME vs USERPROFILE, which matters only for a native Windows bridge. A package joins the list once its tests pass on Windows; the node agent's packages must be on it.
